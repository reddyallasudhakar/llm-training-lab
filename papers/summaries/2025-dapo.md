# DAPO: An Open-Source LLM Reinforcement Learning System at Scale

[arXiv 2503.14476](https://arxiv.org/abs/2503.14476) · Yu et al. (ByteDance Seed, Tsinghua AIR) · Mar 2025 · Lane: Foundations · Module: M22
*One-page summary written by Claude. Your own TLDR goes in `notes/`.*

## TLDR
Plain GRPO on Qwen2.5-32B reached only 30 on AIME 2024. Four fixes to GRPO took it to 50,
beating DeepSeek-R1-Zero-Qwen-32B (47) with half the training steps. Code and data are open.

## The problem
Labs that trained reasoning models with RL left out the details. When the authors ran
"naive" GRPO they hit three failures: **entropy collapse** (samples in a group become nearly
identical, so the model stops exploring), **reward noise**, and **training instability**.

## The mechanism
DAPO keeps GRPO's group-relative advantage but changes the objective. For each question q
it samples G answers o_1..o_G and maximises:

`J = E[ (1 / Σ_i |o_i|) · Σ_i Σ_t min( r_i,t · A_i,t , clip(r_i,t, 1−ε_low, 1+ε_high) · A_i,t ) ]`
subject to `0 < #{ o_i that are correct } < G`

- **r_i,t** = π_θ(token) / π_old(token): how much more likely the new policy makes token t of answer i.
- **A_i,t** = (R_i − mean(R)) / std(R): answer i's reward compared with its group. Every token in an answer gets the same value.
- **R_i** = +1 if the answer is equivalent to the ground truth, −1 otherwise. No reward model.
- **|o_i|** = length of answer i in tokens. **ε_low, ε_high** = how far the ratio may move down or up.
- **No KL term.** The authors argue a reasoning model is meant to drift far from the start model.

The four techniques, and what each fixes in GRPO:
1. **Clip-Higher** (fixes entropy collapse). With one ε = 0.2, a token at probability 0.01
   can rise only to 0.012, while one at 0.9 can go to 1.0. The upper clip blocks rare
   "exploration" tokens. DAPO raises only the upper bound: ε_low = 0.2, ε_high = 0.28.
   Raising ε_low too would push tokens to 0 and collapse sampling.
2. **Dynamic Sampling** (fixes vanishing gradients). If all G answers are right (or all
   wrong), every advantage is 0 and the group adds no gradient. As training goes on, more
   prompts are all-correct, so the useful batch shrinks. DAPO over-samples and drops those
   groups until the batch is full. That is the `0 < #correct < G` constraint.
3. **Token-level policy gradient loss** (fixes per-sample averaging). GRPO averages the loss
   inside each answer, then across answers: `(1/G) Σ_i (1/|o_i|) Σ_t`. A token in a long
   answer then counts for less, so the model can't learn much from good long answers or
   punish gibberish and repetition in bad ones. DAPO divides by the total token count of the
   group instead, so every token weighs the same.
4. **Overlong reward shaping** (fixes reward noise). A correct but truncated answer used to
   get the "wrong" penalty. First, *Overlong Filtering* masks truncated samples out of the
   loss. Then *Soft Overlong Punishment* adds a length penalty:
   `R_length(y) = 0` if |y| ≤ L_max − L_cache; `((L_max − L_cache) − |y|) / L_cache` inside
   the last L_cache tokens; `−1` past L_max. Here L_max = 20,480 and L_cache = 4,096.

## Results
Qwen2.5-32B base, DAPO-Math-17K (17K problems rewritten so every answer is an integer),
AIME 2024 avg@32. Techniques are added one at a time:

| Setup | AIME24 |
|---|---|
| Naive GRPO | 30 |
| + Overlong Filtering | 36 |
| + Clip-Higher | 38 |
| + Soft Overlong Punishment | 41 |
| + Token-level Loss | 42 |
| + Dynamic Sampling (= DAPO) | **50** |
| DeepSeek-R1-Zero-Qwen-32B | 47 |

- Token-level loss adds little accuracy, but the authors say it keeps length growth healthier.
- Dynamic sampling generates more samples but needs fewer steps, so total time isn't much worse.
- Training reward often has little correlation with validation accuracy: the model overfits the train set.

## Limits
- One model (Qwen2.5-32B), one domain (math), one benchmark, and no repeated seeds.
- The ablation is cumulative, so each row's gain depends on the order the fixes were added.
- **Dr. GRPO** (2503.20783), out a week later, argues that dividing by the batch's token count
  (as verl does) still leaves a length bias, and normalises by a constant instead.
- **VAPO** (2504.05118, same group) went back to a learned value model and reported 60.4 on
  AIME 2024, more than 10 points above DAPO in the same setting. Critic-free isn't the final word.

## Why it matters to you
This is your M22 checklist for GRPO on Casefile T3 (adjudicate a claim against the rules engine).
1. **Dynamic sampling:** after SFT many claims will be easy, so every sample gets the verdict
   right and the group teaches nothing. Log the share of zero-advantage groups. If it climbs,
   filter or reweight.
2. **Clip-Higher:** plot entropy from step one. If it collapses early, raise ε_high, not ε_low.
3. **Overlong shaping:** pick a max rationale length that fits your 16 GB M3, and don't
   score truncated audits as wrong verdicts.
4. **Loss reduction:** check which normalisation your trainer uses before comparing runs.

## Words to know
**Entropy collapse:** the policy becomes nearly deterministic too early and stops exploring.
**Clip range (ε):** how far one update may move a token's probability ratio away from 1.
**avg@32:** accuracy averaged over 32 samples per problem.
**Zero-advantage group:** all answers got the same reward, so the group contributes no gradient.
