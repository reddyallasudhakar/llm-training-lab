# GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning

[arXiv 2507.19457](https://arxiv.org/abs/2507.19457) · Agrawal et al. (UC Berkeley, Stanford, Databricks, MIT) · Jul 2025 · Lane: Foundations · Module: M25
*One-page summary written by Claude. Your own TLDR goes in `notes/`.*

## TLDR
Instead of turning each rollout into one scalar reward for a gradient, let an LLM read the
whole trace and the evaluator's feedback, then rewrite the prompt. On Qwen3 8B this beat
GRPO with 24,000 rollouts on 5 of 6 tasks, using up to 35× fewer rollouts. It also beat
MIPROv2, the leading prompt optimiser. Numbers below are from v2 (Feb 2026).

## The problem
GRPO-style RL usually needs tens of thousands of rollouts. Each rollout is squeezed into one
number at the end, even though it contains readable text: reasoning, tool calls, and often
the evaluator's own explanation (a compiler error, a failed rubric). The question: can
learning *in language* get more out of each expensive rollout?

## The mechanism
A system Φ has modules, each with a prompt π_i and weights θ_i. GEPA changes only the
prompts and keeps weights frozen, under a rollout budget B:

`best prompts = argmax over Π of  E[ μ(Φ(x; Π), m) ]   such that  #rollouts ≤ B`

- **x** = task input, **m** = what the evaluator needs (gold answer, rubric, unit tests).
- **μ** = metric in [0, 1]. **μ_f** = a feedback function that returns the score *plus text*
  explaining it (e.g. which documents are still missing, which constraints failed).

The loop (Algorithm 1):
1. Split training data into **D_feedback** (to learn from) and **D_pareto** (to select with).
2. **Select a candidate** from the pool using Pareto sampling (below).
3. **Pick one module** to change, round-robin.
4. Run the candidate on a **minibatch of 3** examples. Collect traces, scores and feedback text.
5. **Reflect:** a reflection LLM gets the current instruction, the inputs, outputs and
   feedback, and is asked to write a new instruction, including any domain facts it learned.
6. If the new prompt scores higher on the minibatch, add it to the pool, record its parent,
   and score it on all of D_pareto. Otherwise discard it.
7. When the budget runs out, return the candidate with the best average on D_pareto.

**Pareto-based selection (Algorithm 2).** For each validation example, find the best score
any candidate has reached. Keep every candidate that is best on at least one example, drop
those strictly dominated, then sample in proportion to how many examples each one wins.
Always mutating the single best prompt gets stuck. This keeps "specialist" prompts alive.

**Merge** (optional): combine modules from two lineages that learned different things.

## Results (test set)
| Qwen3 8B | HotpotQA | IFBench | HoVer | PUPA | AIME-25 | LiveBench-Math | Aggregate |
|---|---|---|---|---|---|---|---|
| Baseline | 42.33 | 36.90 | 35.33 | 80.82 | 27.33 | 48.70 | 45.23 |
| GRPO (24k rollouts) | 43.33 | 35.88 | 38.67 | 86.66 | **38.00** | 51.26 | 48.91 |
| MIPROv2 | 55.33 | 36.22 | 47.33 | 81.55 | 20.00 | 46.60 | 47.84 |
| GEPA | **62.33** | **38.61** | **52.33** | **91.85** | 32.00 | **51.95** | **54.85** |

- GEPA used 1,839–7,051 rollouts per task, against GRPO's fixed 24,000. Most of GEPA's budget
  goes to validation. Counting only training rollouts, it needed 79–737 to reach its best.
- On GPT-4.1 Mini, GEPA+Merge reached a 66.36 aggregate (+13.33), against MIPROv2's +5.64.
- Prompts tuned with Qwen3 8B transferred to GPT-4.1 Mini for +9.00.
- Pareto selection: +12.44 aggregate, against +6.05 for always-mutate-the-best.
- GEPA prompts were up to 9.2× shorter than MIPROv2's.

## Limits
- **GRPO won on AIME** (38 vs 32). Pure reasoning skill seems to need weight updates.
- The GRPO baseline is LoRA rank 16 on a fixed 24k budget with manually tuned settings. A
  full-parameter check was run only on 2-hop HoVer. A stronger RL run could close the gap.
- Merge hurt Qwen3 8B on IFBench (28.23 vs 38.61). When to use it is still open.
- The claims shrank between versions: v1 said "+10% on average over four tasks"; v2 says +6% over six.
- Weights never change, so GEPA can't add knowledge or skill the model lacks.

## Why it matters to you
This is the paper for your key M25 question: when does prompt optimisation replace RL?
The paper's answer: when rollouts are expensive, weights are off-limits, and **the evaluator
can explain itself**. RL still won where the skill itself must change (AIME).
- **Casefile T3 fits GEPA's best case.** Your rules engine can say *which* deduction was
  wrong, which rule applies and the correct amount. That is μ_f.
- **Concrete decision:** before spending A100-hours on GRPO, run GEPA on the SFT model's
  prompt with that feedback. Add a "SFT + GEPA" row to your headline table. If it gets close
  to GRPO, the RL result has to justify its cost. If GRPO wins on amount accuracy, that is
  your AIME case.
- At M24, the same loop can tune a multi-step claims agent where RL per step is hard.

## Words to know
**Rollout:** one run of the system on one input, plus its evaluation.
**Pareto front:** the set of candidates that no other candidate beats on every example.
**Reflective mutation:** an LLM rewrites a prompt after reading traces and feedback.
**Feedback function (μ_f):** a metric that returns text explaining the score, not just a number.
